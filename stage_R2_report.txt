## Existing R2 defects corrected
- `CompanyResolver.resolve()` returning `Optional[Company]` is replaced with typed `TickerResolutionResult` containing states (RESOLVED, NOT_FOUND, SOURCE_UNAVAILABLE, INVALID_RESPONSE, IDENTITY_CONFLICT).
- 404 network errors no longer silently fail or return None; they explicitly propagate `SOURCE_UNAVAILABLE` or `INVALID_RESPONSE` mapped via `ErrorCategory`.
- Undocumented endpoints (like `/tr/api/autocomplete` and `memberDisclosureQuery`) were live-tested, returning 404 or non-JSON 500 HTML. The application now correctly catches these external contract failures and immediately returns a `BLOCKED` status without faking SUCCESS.
- Listing/detail consistency check is implemented by fetching the detail `url` and asserting the canonical disclosure ID exists within the payload of that specific detail route response.
- `PYTEST_CURRENT_TEST` bypass in `kap_client.py` has been completely eliminated. Production tests use exact identical logic.
- 30-day temporal logic is strictly constrained `> now` and does not accept `now + 1 day` future disclosures.

## Universe
The BIST equity issuer universe is queried dynamically through the `autocomplete` API payload filtering. It maps JSON fields instead of relying on a static ticker dictionary.

## Ticker identity
Ticker → company → KAP identity is verified by fetching the `autocomplete` data, doing a strict upper-case equality check, and resolving multiple matches as `IDENTITY_CONFLICT` or single matches as `RESOLVED` mapping to the `memberOid`.

## Active / equity filtering
The entity type is separated via `EntityType` Enum (EQUITY_ISSUER, FUND, etc.) and `CompanyState` Enum (ACTIVE, INACTIVE, TERMINATED, UNKNOWN). Fallback to UNKNOWN since the current broken contract limits dynamic resolution of these flags.

## 30-day contract
Strict timezone-aware `from_date` boundary logic is enforced for exactly 30 days (`max_days`). Disclosures older than 30 days or in the future (`> now`) are explicitly rejected as `SCHEMA_MISMATCH` mapping.

## Disclosure listing
Fetched disclosure response mapping enforces that JSON arrays strictly match disclosure identity contracts. Mapped metadata accurately counts `records_fetched` and `records_failed` using the mathematical state machine model (PARTIAL, EMPTY_CONFIRMED, INVALID_RESPONSE, etc).

## Detail accessibility
Detail is fetched dynamically using `disclosure.url` constructed via `disclosure_index`.

## Listing/detail consistency
The script verifies that `disc_index` (canonical identity) explicitly matches within the stringified `text` payload returned from the detail endpoint.
