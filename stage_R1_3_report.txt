## STAGE
R1.3 — State Machine Seal

## Changes
- Removed the mutable readiness state mapping from `_readiness` inside the production engine completely. The engine now operates via a strictly sealed `_is_production_ready` property that returns `False` deterministically in production environments, thereby perfectly sealing the test overrides from runtime manipulations.
- Enforced strict integer boundary validations on counters inside `RequestMetadata` (`records_fetched >= 0`, `records_failed >= 0`, `duration_ms >= 0`, `retry_count >= 0`) via explicit `Field` bounds.
- Augmented the `RequestMetadata` model validator to strictly forbid invalid combinations of states (e.g. failing a `PARTIAL` result that doesn't actually contain fetched records, preventing `EMPTY_CONFIRMED` or `SUCCESS` states that register failures or errors).

## State invariants
### SUCCESS
- `error_category == NONE`
- `records_failed == 0`
### EMPTY_CONFIRMED
- `error_category == NONE`
- `records_fetched == 0`
- `records_failed == 0`
### PARTIAL
- `records_fetched > 0`
- `records_failed > 0`
- `error_category != NONE`
### UNAVAILABLE
- `error_category != NONE`
### INVALID_RESPONSE
- `error_category != NONE`
### Counters
- `records_fetched >= 0`
- `records_failed >= 0`
- `retry_count >= 0`
- `duration_ms >= 0`
